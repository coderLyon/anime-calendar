# 《动漫追番日历》开发文档 v8（原型先行门禁）

## 1. 可行性结论与风险

**结论：可行。** 原型已打通四平台周更数据的抓取、去重与周一~周日看板展示；新增规则（时长过滤、最新集直达、移动端适配）不改变整体架构。唯一结构性改动：原抓取跑在 Vite 开发服务器插件里，而 GitHub Pages 只能托管静态文件，因此改为「GitHub Actions 定时抓取 → 清洗生成数据文件 → 静态前端读取」。

**执行门禁（硬性要求）**：整体计划以 **G0：设计原型先行并通过审批** 为前置条件；**审批通过前不执行任何实现工作**（不建仓、不迁移代码、不写代码、不部署）。门禁只要求「先出完整可审批的设计原型」，不指定实现工具。

**重要语义（用户确认）**：内容黑名单（小课堂/发布会/预告等非正剧词）**只影响最新集判断**——在解析最新一集时跳过这些条目；**不参与周表的过滤**，周表按平台原始更新数据展示。

| 风险 | 影响 | 对策 |
|---|---|---|
| 腾讯/爱奇艺为客户端渲染，选择器含 hash 会随改版失效 | 平台抓取失败 | 沿用「失败即 throw」约定，编排器写 `error` 字段；README 记录结构探针；Actions 日志输出失败告警 |
| 时长字段各平台不一定内联提供 | 时长过滤失效 | 两级策略：优先读页面内联时长；缺失时对去重后的唯一番剧做封面页富集（平台+番剧缓存，单次上限 ~40 次）；仍缺失用「动态漫/AI动漫/泡面番」关键词兜底并记入 `warnings` |
| 预告片/片花/小课堂穿插在剧集列表中间 | 最新集跳到非正剧 | 最新集解析按黑名单跳过后再取最大正剧集数，不以 DOM 顺序取末项；解析结果带缓存 |
| Actions 出口 IP 可能被平台风控/限流 | 数据缺失 | 保持浏览器 UA/Referer/超时；失败平台保留上次成功数据合并输出 |
| Actions 定时任务最小粒度 1 小时且有调度抖动 | 数据有延迟 | 默认每天 07:00/19:00（Asia/Shanghai）两次 + 手动触发 + 本地 `npm run sync` 兜底 |
| 追番记录存 localStorage | 清缓存/换设备丢失 | 提供导出/导入 JSON；文档明确单用户特性 |
| Playwright Chromium 安装体积大 | Actions 变慢 | 只安装 chromium 频道并缓存 `~/.cache/ms-playwright` |
| 移动端图片与 JSON 流量较大 | 弱网加载慢、耗流量 | 海报懒加载+占位、`updates.json` gzip（Pages 自动）、必要时按平台拆分 JSON 懒加载（>1MB 时启用） |

## 2. 执行门禁：设计原型先行（G0）

### 2.1 原则与流程

- **硬性门禁**：G0 未通过前，**禁止**进行 M0 建仓、代码迁移、`npm` 安装、接口开发、部署等任何实现动作；允许的只有信息收集与只读探索。
- **工具不限**：原型可用 Figma、ImageGen 概念图 + 标注、可交互 HTML 原型、本地设计稿等任一方式产出，只以「完整、可审批、可直接指导实现」为质量标准；执行环境优先选择能最快产出该质量的工具。
- 流程：产出完整设计原型 → 交付用户审批 → 未通过则按意见迭代重出 → **审批通过后原型锁定为设计规范（design spec）**，实现阶段零自由发挥，任何布局/文案/配色/交互变更需重新过审。

### 2.2 原型画布清单（必须完整覆盖）

- **首页**（桌面 1440 与移动 390 两套）：Header（标题、「追番日历」按钮、「刷新」按钮）、四平台 Tab、周一~周日周看板（今日列高亮）、卡片全形态（海报、集数、更新时间、SVIP、独播徽章、已追番星标态、点击跳转）。
- **追番列表**：追番入口页，含搜索框、平台筛选、追番项展开多平台链接、导出/导入入口、空态。
- **日历三视图**：日程视图（当天更新列表 + 空态 + 明日预览）、周视图（7 列网格 + 今天定位）、月视图（月历 + 每日数量角标 + 当日列表），桌面与移动各一版。
- **状态稿**：加载骨架屏、平台抓取失败、数据为空、`warnings` 提示、深色模式（可选）。
- **交互标注**：Tab/星期切换、左右滑动切换日期、追番星标 toggle、卡片跳最新集、日历视图切换与「回到今天」。

### 2.3 原型需携带的设计系统

- **设计 tokens**：配色（含四平台品牌色）、字体（字号/字重/行高）、间距、圆角、阴影、边框、图标风格。
- **组件族**：卡片、Tab、按钮、搜索框、日历格、Segmented 视图切换、空态/骨架屏。
- **响应式规则**：桌面 7 列看板；<768px 周看板/周历退化为「星期 Tab + 单日列表」；月历格压缩为「日期+数量角标」。
- **交付位置**：原型导出 PNG 存入 `outputs/design/`，原型文件（或链接）随文档一并交付，供实现期逐屏对比。

## 3. 四平台抓取接口详解

四个平台目标统一：输出同一份 `AnimeItem` 结构（契约见第 4 节）。抓取分两类——B站/优酷为 **SSR 静态解析**（普通 HTTP fetch），腾讯/爱奇艺为 **Playwright 无头浏览器渲染**。公共工具在 `shared.mjs`：`fetchText`（浏览器 UA、25s 超时）、`extractAssignedObject`、`parseJsObject`、`httpsImg/normUrl`、`ymd/addDays/zhWeekday`、`epKey/normalizeTitle`、`sortByDateThenTime`。

### 3.1 哔哩哔哩国创（`bilibili.mjs`，SSR）

- **入口**：`GET https://www.bilibili.com/guochuang/`，带 `Referer` 与浏览器 UA；解析 `window.__INITIAL_STATE__.modules.ext[]` 中「items 含 episodes[]」的时间表模块。
- **字段映射**：`episode_id/season_id/title`→`id`；`title`→`title`；`cover/square_cover/ep_cover`→`poster`；`pub_index`→`episode`；`pub_time+星期`→`updateTime`；`pub_ts`→`date`；`link/episode_id`→`url`；`rating`→`badge`。**`day_of_week===0`（最近更新聚合组）必须跳过**。
- **时长来源**：优先读时间表条目内联 `duration`（秒）；缺失时对唯一番剧做剧集页富集，读 `window.__INITIAL_STATE__.videoInfo.timelength`（毫秒→秒）。
- **最新集规则**：优先拼 `bangumi/play/ep{episode_id}`（周表条目即该周最新发布集）；若 URL 是 season 页（`/ss`），富集时跳转最新 `/ep` 页，剧集列表按黑名单跳过非正剧条目后取最大集数。
- **去重**：`dedupSvip`（兜底同集重复）。

### 3.2 优酷动漫（`youku.mjs`，SSR）

- **入口**：`GET https://www.youku.com/ku/webcomic`；`window.__INITIAL_DATA__` 经 `parseJsObject` 清洗后解析「每日更新」模块（`tabList` 7 个星期 tab，「今」=今天；`itemList` 7 个数组一一对应）。
- **字段映射**：`title/trackInfo.object_title`→`title`；`img/hImg`→`poster`；`lbTexts`→`episode`；`reason.text.title`→`updateTime`（含「10:00 SVIP更新1话」）；`mark.text/iconfont`→`badge`；`action_value`→show id。**SVIP 抢先**只看 reason 含 "SVIP"；`mark.iconfont==="SVIP"` 只是独家内容，不算抢先。
- **时长来源**：优先读条目内联时长字段（`duration`/`dur`，需归一为秒）；缺失时用 `show_page` 富集分集数据。
- **最新集规则**：`url` 拼 `https://www.youku.com/show_page/id_{showId}.html`（302 跳播放页；`v_show` 会 404 禁止用）。富集时校验落地页目标是否为最新正剧集：分集列表按黑名单跳过非正剧条目后取最大集数，避免落到小课堂/发布会/预告。
- **去重**：`dedupSvip`（保留 SVIP 抢先日，删后一天同标题同集常规条目）。

### 3.3 腾讯视频动漫（`tencent.mjs`，Playwright）

- **入口**：`https://v.qq.com/channel/cartoon`，Playwright 逐 tab 点击星期栏（`.video-banner__tabname--schedule`，跳过 `#fakeTab`），tab 的 `dt-params` 含 `week=YYYYMMDD` 真实日期；卡片 `.banner-card--web` 限定在含「每日更新」的 `.video-banner` 容器内。Chromium 不可用时降级 SSR 兜底（`mzTitle/coverPic`，无集数无日期，仅保底）。
- **字段映射**：标题 `.banner-card__title[title]`；海报取 `dt-params` 的 `link=`（decodeURIComponent）；`cid/vid` 取 `dt-params`；集数正则 `更新至X集/更新至ⅡX/全X集`；badge 正则 `限免中|独播|上新|结局点映|大结局|高清修复`。
- **时长来源**：优先读卡片 `dt-params` 或数据属性中的时长；缺失时在封面页富集时一并读取目标集时长。
- **最新集规则（含穿插预告处理）**：有 `vid` 直接用 `/x/page/{vid}.html`；否则封面页富集 `extractLatestVid`：切到最后一个数字区间 tab → 从后向前扫描整个 `.episode-list`，跳过黑名单条目（预告|preview|片花|花絮|先导|抢鲜看|小课堂|发布会…）→ 取编号最大的真实正剧集（不以 DOM 末项为准）→ 读 `dt-params` 的 vid，读不到则点击后从 URL 提取。
- **去重管线（顺序固定）**：`dedupAdjacentSvipEarly`（相邻两天同标题同集=SVIP 抢先，留早删晚）→ `dedupFinaleEarlyRelease`（结局点映只留首日）→ `dedupMonSunSameWeek`（同周周一+周日同集留周日）。

### 3.4 爱奇艺动漫（`iqiyi.mjs`，Playwright）

- **入口**：`https://www.iqiyi.com/dongman/`，Playwright 逐日点击星期 tab（`.videoCards_tab_btn__RXUQe`，当天用「今天」tab 避免重复），点击前后 `dismissOverlay`（移除 `fullCover` 遮挡层）；卡片 `.filmFeed_followCalendarCard__O1NDf`，读取时回溯到含 tab 栏的容器。
- **字段映射**：文案区 `[data-ai-entity="文案区"]` 内 `<a>`→`title`（经 `cleanTitle`）；海报 `<a href>`+`<img src/data-src>`→`url/poster`；`[data-content]`→`episode`；`updateTime`=「周X更新」；`date`=本周一+(dow-1)。
- **周表有效性过滤（保留原型，仅去非更新占位）**：原始文本过滤 `即将上线|敬请期待|马上看|预约|限时`（这些不是当天更新条目）；「动态漫」由时长规则统一处理。
- **时长来源**：优先读卡片数据属性；缺失时对唯一番剧的播放页「选集」面板富集时长。
- **最新集规则**：widget 的 `<a href>` 可能指向剧集页或总集页；富集时打开播放页选集面板，跳过黑名单条目（预告|片花|花絮|抢先看|先导|小课堂|发布会…）后取最大正剧集的链接。
- **去重**：按 `(title, date)` 去重后排序。

### 3.5 统一清洗层（顺序固定）

`scripts/sync.mjs` 内每个平台数据按以下顺序处理：

1. **时长过滤（<10 分钟）**：`AnimeItem.duration`（秒）非空且 `< 600` → 丢弃（泡面番/AI动漫/动态漫即此类）；时长缺失的条目在**去重之后**按唯一番剧批量富集（平台+番剧缓存，单次上限 40 次），仍缺失时命中 `动态漫|AI动漫|泡面番` 关键词也丢弃，并记入 `warnings`。
2. **原有去重管线**：按平台各自的 SVIP/结局点映/周一+周日规则执行（见 3.1~3.4）。
3. **最新集 URL 解析（黑名单唯一生效处）**：对去重后的条目解析/校验直达链接。`CONTENT_BLOCKLIST` 常量（默认：`小课堂|发布会|预告|片花|花絮|幕后|访谈|见面会|先导|抢鲜看`，可配置）**仅在此步使用**：扫描剧集列表时跳过命中条目，再按集数取最大真实正剧集，不以 DOM 顺序取末项；解析结果写入 `AnimeItem.url` 并按 (platform, title/cid) 缓存。**周表展示不做黑名单过滤**。
4. **统一输出**：`{ platform, label, items, fetchedAt, warnings? }`，失败平台 throw（编排器包装 `items:[] + error`）。

## 4. 总体架构与数据流

**架构**：GitHub Pages 静态前端 + GitHub Actions 定时数据管道。

**数据流**：Actions（`schedule` cron + `workflow_dispatch` + push 触发）→ `npm ci` → `npx playwright install chromium` → `node scripts/sync.mjs`（抓取 → 时长过滤 → 去重 → 最新集解析 → 写 `data/updates.json`）→ `vite build` → `actions/deploy-pages` 发布 `dist`。本地 `npm run sync` 同样可生成数据文件手动提交兜底。

**数据契约**：
- `AnimeItem`：`id / platform / title / poster / episode / updateTime / date("YYYY-MM-DD") / svip / url / badge`，新增可选 `duration?: number`（秒）。
- `PlatformResult`：`platform / label / items / error / fetchedAt`，新增可选 `warnings?: string[]`（如时长无法确认被关键词兜底剔除的条目）。
- 新增 `FollowItem`：`{ key: 规范化标题, title, platforms: [{platform, url, episode, poster}], followedAt }`。
- `updates.json`：`{ generatedAt, platforms: PlatformResult[] }`；前端追番状态存 `localStorage["anime-calendar.follows.v1"]`。

## 5. GitHub 仓库规划

### 5.1 仓库形态

- **名称**：`anime-calendar`（占位，可按喜好改）；**可见性：公开**（公开仓库可免费使用 Pages 与 Actions，且适合分享）；如需私有，改可见性即可，其余规划不变。
- **默认分支**：`main`；**分支策略：主干开发**——单人维护直接在 main 提交；多人协作用短期功能分支 + PR 合入 main（squash merge）。
- **许可**：`MIT`（公开个人项目）；README 注明「数据版权归各平台，仅供个人追番参考，请勿商用」。
- **提交规范**：Conventional Commits（`feat:` / `fix:` / `refactor:` / `chore:` / `docs:`），与原型 AGENTS.md 约定一致。

### 5.2 Actions 工作流（`.github/workflows/deploy.yml`）

- **触发**：`schedule` cron `0 11,23 * * *`（UTC，即北京 07:00/19:00）；`workflow_dispatch`（手动）；`push` 到 main（代码变更即重新构建部署）。
- **权限**：`contents: read`、`pages: write`、`id-token: write`；`concurrency: { group: "pages", cancel-in-progress: false }`（防止定时与手动任务互相打断）。
- **步骤**：checkout → setup-node（v22，npm 缓存）→ `npm ci` → `npx playwright install chromium`（缓存 `~/.cache/ms-playwright`）→ `node scripts/sync.mjs` → `vite build` → `actions/configure-pages` + `upload-pages-artifact` + `deploy-pages`（用官方 actions 当前最新 major，安装时以官方文档为准）。
- **失败策略**：`sync.mjs` 内部按平台隔离错误，单平台失败仍写出 `updates.json`（该平台 `error` 字段 + 保留上次成功数据）并正常部署；**只有完全无法产出数据时才退出非零**，让工作流失败并保留上次部署。
- **配额**：公开仓库免费 2000 分钟/月；按每天 2 次、每次约 10~15 分钟估算约 600~900 分钟/月，加上 push 构建，余量充足。

### 5.3 Pages 配置

- **来源**：Settings → Pages → Source 选 **GitHub Actions**（由工作流产物部署，不需要分支部署）。
- **路径**：项目页地址为 `https://<owner>.github.io/anime-calendar/`，因此 **`vite.config.ts` 必须配置 `base: '/anime-calendar/'`**（或按环境变量注入，防止静态资源 404）。
- **域名**：默认用 `*.github.io` 子路径；如需自定义域名，加 `CNAME` 记录并在 Pages 设置绑定（可选，后续再做）。
- **HTTPS**：Pages 默认强制 HTTPS（移动端通知/Service Worker 等能力依赖 HTTPS，天然满足）。

### 5.4 仓库文件清单

- 必建：`README.md`（简介、功能、数据来源与免责声明、本地运行、手动同步、架构说明、目录结构、许可）、`.gitignore`（`node_modules/`、`dist/`、`*.bak`）、`LICENSE`（MIT）、`.github/workflows/deploy.yml`。
- 随项目迁移：`server/`（四抓取器 + shared）、`src/`、`vite.config.ts`（补 base 配置）、`package.json`、`tsconfig*.json`、`index.html`。
- 新增：`scripts/sync.mjs`（清洗管线入口）、`data/updates.json`（由本地 `npm run sync` 生成，**可选手动提交**供无 Actions 时访问；线上部署用工作流内生成的同一文件，避免 bot 提交污染历史）。
- 可选：`AGENTS.md`（给后续 AI/协作者的项目指南）、issue/PR 模板、`SECURITY.md`。

### 5.5 首次上线清单

1. 用 GitHub app（或网页）创建公开仓库 `anime-calendar`，本地 `git init` 后推送 main。
2. 确认 Settings → Pages → Source = GitHub Actions；`vite.config.ts` 的 `base` 与仓库名一致。
3. 推送后首次运行会触发 push 构建；再手动 `workflow_dispatch` 一次完整抓取流程（含 Playwright 安装）。
4. 打开 `https://<owner>.github.io/anime-calendar/` 验证：数据为最新、四平台看板正常、卡片可访问。
5. 后续日常维护：改代码走 main/PR；数据异常时本地 `npm run sync` + 手动提交 `data/updates.json` 兜底。
6. 说明：本机未安装 `gh` CLI，仓库创建与设置统一走 GitHub app 或网页操作。

## 6. 功能规格与人性化优化

- **首页**：四平台 Tab + 周一~周日横向看板（沿用 WeekdayBoard），今日列高亮；卡片含海报/集数/更新时间/SVIP/独播徽章，**点击卡片直达该番最新正剧集**（黑名单仅保证解析到的「最新集」不是小课堂/发布会/预告）；失败 Tab 显示失败标签与重试。
- **追番收藏**：卡片星标记录/取消；右上角追番数与列表；同标题跨平台合并；追番列表搜索、平台筛选、导出/导入。
- **追番日历**：右上角进入，默认仅显示已追番（可切「全部番剧」）：日程视图 = 当天更新列表（时间/平台色/直达链接，无更新显示空态+明日预览）；周视图 = 7 列网格 + 「今天」定位；月视图 = 月历网格 + 每日数量角标与缩略列表，支持跨月翻页。
- **人性化优化**：今日更新摘要横幅；关键词搜索与 SVIP/独播/限免筛选；「N 小时前更新」提示与 `warnings` 提示；深色模式（跟随系统）；骨架屏/重试/空态；键盘可达；已追番卡片统一高亮；可选浏览器今日更新通知。
- **UI 规范**：实现严格对照第 2 节已批准原型；设计 tokens 与组件族取自原型，实现中不得自由发挥。

## 7. 移动端适配规划

### 7.1 断点与布局

- 断点：**<768px 为移动端**（含 375/390/360px 主流手机），768~1023px 平板，≥1024px 桌面；核心判断用媒体查询 + 容器查询（卡片内部）。
- **周看板移动端退化（关键决策）**：桌面保持周一~周日 7 列看板；<768px 时切换为「星期 Tab（周一~周日，今天默认选中并高亮）+ 单日卡片列表」模式，左右滑动切换相邻星期。
- **日历三视图移动端**：日程视图 = 单列时间线列表；周视图 = 「星期 Tab + 单日列表」；月视图 = 7 列月历压缩为「日期 + 更新数量角标」，点日期进入当日列表。
- **卡片**：移动端单列，海报固定宽高比（`aspect-ratio` + `object-fit: cover`），标题最多两行省略，标签不换行。
- **Header/Tab**：标题字号压缩；「追番日历」「刷新」按钮窄屏图标为主（文字可隐藏）；四平台 Tab 横向滚动；视图切换用 Segmented 控件。

### 7.2 触摸与交互

- 所有可点目标（星标、Tab、按钮）命中区 **≥44×44px**；卡片整卡可点，星标按钮不触发跳转（stopPropagation）。
- 星期/日期切换支持**左右滑动**；`hover` 效果仅在 `(hover: hover)` 设备启用，避免触屏粘滞。
- 「回到今天」按钮在日历与周看板均可用；列表滚动回到顶部；可选下拉刷新，v1 以手动刷新按钮兜底。

### 7.3 性能与流量（手机浏览器）

- `index.html` 加 `viewport`（含 `viewport-fit=cover`）、`theme-color`；`updates.json` 依赖 Pages 自动 gzip（构建时确认 Content-Encoding）。
- 海报全部 `loading="lazy"` + 固定尺寸占位，`referrerPolicy="no-referrer"`（沿用原型防盗链方案）。
- v1 单文件 `updates.json` 全量加载；**若实际体积 >1MB 或首屏超 3s（3G 模拟）则拆分**为 `data/{platform}.json` 并按 Tab 懒加载。
- 控件字体用固定 px/rem 规范 + `text-size-adjust`，避免 iOS 横屏/输入缩放；动画遵循 `prefers-reduced-motion`。

### 7.4 兼容与安全区

- 支持 iOS Safari ≥15、Android Chrome/Edge 最新两版；桌面 Chrome/Edge/Firefox 最新两版。
- 刘海屏/全面屏：固定 Header/操作区使用 `env(safe-area-inset-*)` 内边距。
- 追番数据仅存本机 localStorage，提供导出/导入；浏览器通知为可选能力（仅 HTTPS 生效，拒绝后静默降级为站内角标）。

## 9. 假设与默认决策

- 已确认：Actions+Pages 托管；追番为「收藏+日历」（单用户、localStorage、无账号）；动漫范围维持原型（B站国创 + 腾讯/优酷/爱奇艺动漫频道），B站番剧（日番）列为后续可选迭代；网页必须适配手机浏览器；**设计原型审批通过前不执行任何实现**。
- 门禁默认：G0 只要求「先出完整可审批的设计原型」，**不限定工具**（Figma / ImageGen 概念图 + 标注 / 可交互 HTML 原型等均可）；原型导出 PNG 存 `outputs/design/`；审批通过后变更需重新过审。
- 内容规则：`CONTENT_BLOCKLIST`（默认 `小课堂|发布会|预告|片花|花絮|幕后|访谈|见面会|先导|抢鲜看`）**仅用于最新集解析，不参与周表过滤**；特别篇/番外/剧场版默认视作正剧候选。时长阈值 **<600 秒**；时长缺失且无法富集时用「动态漫/AI动漫/泡面番」关键词兜底并记入 `warnings`。
- 仓库默认：公开仓库 `anime-calendar`、`main` 主干开发、MIT 许可、Actions 产物部署 Pages、`base` 配置与仓库名一致、数据文件可选手动提交、无需任何 Secrets。
- 移动端默认：**<768px 时周看板/周历退化为「星期 Tab + 单日列表」**；支持 iOS Safari ≥15 与 Android Chrome 最新两版；v1 单文件数据加载，>1MB 或弱网超 3s 才拆分；通知可选授权。
