# 《动漫追番日历》迭代计划书 v1 —— 提醒效率 + 匿名云同步

> 状态：**已批准**（2026-08-02 用户确认实施）；本计划书作为对 G0 设计规范的增量过审依据，新增 UI 一律沿用现有 tokens 与组件体系。

## 摘要

本站核心能力（四平台周更看板、追番收藏、日历三视图、短剧过滤、最新集直达）已上线并稳定运行，但对照“正常网站”缺少提醒、数据同步、全局搜索、多周浏览、PWA/离线、SEO、真实刷新等外围能力。本期方向为**提醒与效率优先**，提醒形态为**站内 + 浏览器通知**；个性化数据采用**无账号体系的匿名设备云同步（Supabase 匿名身份），可选绑定邮箱升级**，复刻「开箱即用、匿名即全新」的扩展式体验。

| 能力 | 正常网站 | 本站现状 | 处置 |

## 一期实施方案（M5）

### 数据管道与基础工程

- **CI bot 回写**：sync 完成后由 Actions 将 `data/updates.json` + `data/history.json` 以 GITHUB_TOKEN 提交回 main（提交信息含 `[skip ci]`；GITHUB_TOKEN 提交本身不触发新 run，双保险）。工作流权限增加 `contents: write`。
- **历史归档**：同步时把每周真实条目（不含 predicted）按 `weekStart` 写入滚动归档 `history.json`，保留最近 8 周；前端仅切到历史周时懒加载。
- **真实刷新**：Header「刷新」改为运行时请求 `https://raw.githubusercontent.com/coderLyon/anime-calendar/main/data/updates.json`（带时间戳防缓存），对比 `generatedAt` 更新内存数据；失败/离线回退构建时数据并提示，移除模拟骨架动画。
- **PWA**：接入 `vite-plugin-pwa`——manifest（名称/图标 192+512/主题色/standalone）+ service worker 预缓存构建产物与最近一次 updates.json，离线可打开看板。
- **SEO/分享**：index.html 补 og/twitter/JSON-LD；新增 `robots.txt`、`sitemap.xml`、`404.html`；移动端 `navigator.share`、桌面复制链接。
- **URL 状态同步**：`?platform/&week/&day/&view/&scope/&show=` 经 `history.replaceState` 保持，支持深链与分享；兼容现有 `p/state/theme` 参数。
- **稳定性与性能**：全局 ErrorBoundary（fallback + 重新加载）；Toast/横幅补 `aria-live`、加 skip-link；`<link rel=preconnect>` 指向四个海报 CDN；README 增加 Actions 状态徽章。

### 匿名设备云同步（无账号体系）

- 接入 `@supabase/supabase-js`，环境变量 `VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY`（公开 anon key + RLS 隔离；提交 `.env.example`，CI 经仓库变量注入）。
- **匿名优先**：首次访问静默 `signInAnonymously` 创建设备匿名身份——无登录界面、无注册流程、开箱即用；同一设备数据存云端并自动同步；新设备/清空站点数据 = 新匿名身份 = 空白开始。
- **可选邮箱绑定**：设置页提供「绑定邮箱」入口（`updateUser({ email })`），把匿名身份升级为邮箱身份后实现真正跨设备；不绑定则保持设备级匿名。
- 表结构与 RLS（匿名/邮箱用户均只可读写本人行）：`follows(user_id,key,title,platforms,updated_at)`、`blocked(user_id,key,title,blocked_at)`、`settings(user_id,theme,shortfilter_enabled,shortfilter_threshold)`、`notify_log(user_id,date,show_key,notified_at)`。
- 同步策略：本地优先（offline-first）——本地写操作即时生效并入队，启动/切回前台/变更后（防抖）拉取合并；冲突按记录级 `updated_at` 后写覆盖；拉取后本地删除远端已不存在的 key。
- **身份与兜底**：localStorage 保留现有键作为本地数据与匿名会话（`anime-calendar.session.v1`）存储；清空站点数据会导致匿名身份凭证丢失，保留导出/导入 JSON，并在设置提示「建议绑定邮箱或定期导出」。
- Header 显示轻量同步状态（本机/已同步/同步中/离线），不出现“登录”字样。

### 提醒（站内 + 浏览器通知）

- Header 新增铃铛：显示今日追番更新数角标；点击时（用户手势）请求通知权限，拒绝后仅站内角标 + Toast。
- 仅提醒「已追番且当日有更新」的剧集；追番列表提供逐剧「提醒」开关（默认开）；同一剧集同一天只提醒一次（身份走 `notify_log`，游客回退 `anime-calendar.notified.v1`）。
- 触发时机：页面加载、切回前台、每 30 分钟站内检查、手动刷新后；聚合文案「今日 N 部追番更新：《A》《B》…」。
- 边界：浏览器通知仅在网站打开时有效；Periodic Background Sync 列为远期；通知偏好随匿名身份同步。

### 效率功能

- **全站搜索**：看板工具栏加搜索框（`/` 快捷聚焦，按规范化标题模糊匹配），结果就地过滤 7 行看板与今日摘要，空态提示「无匹配」。
- **多维度筛选**：徽章 chips（独播/SVIP抢先/限免/超前点映/结局点映/大结局/完结）+「只看连载」开关，与平台 Tab、搜索、短剧过滤叠加生效。
- **断更检测**：前端解析 `rule`（每周X…时间）与完结标记；已追番剧若规则日当天（宽限至更新时间 +2h）无更新条目且非完结，标记「疑似断更」，展示于追番列表与日历当日，可「忽略」并持久化；无规则数据不检测。
- **多周导航**：看板头部「‹ 上一周 / 本周 / 下一周 ›」+「回到本周」；范围 = 历史 8 周（懒加载）+ 本周 + 下周预计（标「预计」）；历史周无数据时显示空态说明。
- **信息增强**：卡片 meta 显示时长（约 N 分钟，不足 60s 显示秒）；「数据更新于」改相对时间（N 分钟/小时前，hover 显示精确时间）；今日摘要同步响应筛选。

### 接口/类型/契约变更汇总

- 新增 `HistoryFile` 类型、`VITE_SUPABASE_URL/ANON_KEY` 环境变量、4 张 Supabase 表、URL 参数 `platform/week/day/view/scope/show`、存储键 `anime-calendar.notified.v1` 与 `anime-calendar.session.v1`；`AnimeItem` 契约不变。
- 新增组件：SearchBox、FilterChips、WeekNav、NotificationBell、SyncStatus、ErrorBoundary，全部基于现有 tokens。

## 二期与远期（Backlog）

- **二期**：剧集详情/历史面板、豆瓣评分链接、卡片「纠错」入口（预填 GitHub Issue）、Actions 失败自动建 Issue、RSS/ICS 订阅导出、Web Push 或 Periodic Background Sync、Chrome 扩展伴侣（`chrome.storage.sync` 真正的浏览器账号同步，若确有扩展需求再做）。
- **远期**：自定义域名、隐私友好统计（默认不采集）、多用户公开分享、数据版权合规页与隐私说明。

## 测试与验收

- **单元测试（Vitest）**：日期/周计算、normTitle、短剧过滤、follows 合并与冲突 LWW、rule 解析、断更判定、通知去重、history 归档裁剪。
- **同步专项**：匿名身份自动创建与同设备恢复；新设备/清站数据后为新匿名身份；绑定邮箱后数据迁移；断网写入排队、恢复后合并；冲突后写覆盖。
- **管道验证**：本地 sync 后 updates.json/history.json 结构校验；bot 回写 dry-run 无脏数据；历史归档 8 周上限。
- **E2E（Playwright）**：游客全流程回归；匿名同步全路径（测试项目或 mock）；通知授权允许/拒绝两路径；断更标记与忽略；周导航与历史懒加载；真实刷新成功与离线回退；PWA 注册与离线重载；断点矩阵 375/390/768/1024 + 深色 + 零控制台错误。
- **验收标准**：一期功能全部线上可用；旧功能零回归；无横向溢出与控制台错误；每次修改后自动提交 → 推送 → 验证部署。

## 假设与默认决策

- Supabase 免费层 + 匿名身份；无任何强制登录/注册流程；邮箱绑定纯可选。
- 通知仅站内/浏览器，不做后台推送服务；游客模式与匿名身份体验一致。
- 清空站点数据 = 新匿名身份，云端旧匿名数据不可找回；导出/导入与邮箱绑定作为兜底。
- history.json 依赖 CI 每日两次回写，历史覆盖从接入日起逐步累积；缺失周显示空态而非伪造。
- 新增 UI 按现有设计 tokens 实现；本计划书获批即视为对 G0 规范的增量过审。
- 数据版权与免责声明维持不变，项目仍为个人非商用用途。
