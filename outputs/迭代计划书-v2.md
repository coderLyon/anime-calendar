# 《动漫追番日历》迭代计划书 v2：安全加固、云同步闭环与设备配对

> 状态：**待审批实施**（2026-08-05 规划）。本计划承接 v1 中部分完成和未完成内容。任何新增 UI 先更新已审批设计规范/原型并重新过审；实现阶段继续遵守 `outputs/design/设计规范-design-spec.md`，不得自由改变布局、文案、配色或交互。

## 1. 目标与边界

v2 的首要目标不是继续堆功能，而是把已经存在但未完成端到端验收的云同步、通知和深链能力闭环，并把安全扫描识别出的防御纵深缺口转化为可测试的工程控制。在这些基础稳定后，再实施一次性设备配对和低风险体验扩展。

本期不包含：长期共享“空间码”、后台 Web Push 服务、公开多用户社区、统计追踪、付费能力或自定义域名。它们保留在后续候选池，不作为 v2 交付承诺。

## 3. 安全扫描输入

基线扫描 `64ea6e1d-0d9e-44a9-be70-05048ef820ae` 对提交 `497e971d...` 完成 73/73 文件覆盖，最终无可报告漏洞。以下内容属于**防御纵深与可验证性改进**，不得描述为已存在漏洞：

1. 对 `updates.json`、`history.json`、追番导入文件和 Supabase 远端行实施统一结构、数量、字符串长度和枚举校验。
2. 所有剧集链接/海报只接受 HTTPS，并按平台允许主机；导入链接必须与所声明平台一致。

4. 用 `AbortController` 贯穿平台超时，确保 `Promise.race` 结束时真正取消 fetch/Playwright 工作并清理浏览器。
5. Actions 日志统一去除 CR/LF 或编码以 `::` 开头的行，避免上游文本形成 workflow command。

## 4. 迭代优先级

### P0：云同步正确性与真实验收

目标：只有在两个独立浏览器上下文通过真实后端往返后，才把“匿名云同步”标为完成。

- 建立 Supabase 测试项目或隔离 schema，CI/本地均不得使用生产用户数据。
- 修正 JSONB 契约：`platforms`、`ignore_missed` 按 JSON 数组写入并读回，禁止把 JSON 字符串误存为 JSONB 字符串。
- 修正首次设置合并：新设备没有本地同步时间戳时，必须拉取远端设置，不能用“当前时间”的本地默认值覆盖远端。
- 明确并同步 `poster`、逐剧 `notify`、平台级追番信息；缺失字段采用向后兼容默认值。
- 对远端行和导入文件复用同一 schema validator；无效行隔离并提示，不能覆盖 last-known-good 本地状态。
- 覆盖匿名会话恢复、离线队列、删除墓碑、冲突 LWW、清站点数据新身份、邮箱绑定迁移。
- 增加线上配置检查：构建产物确认 Supabase 已启用；只读核对 RLS、索引和约束。

验收标准：两设备上下文对追番、屏蔽、主题、短剧阈值、断更忽略和通知偏好完成新增/修改/删除双向收敛；断网写入恢复后收敛；跨用户读取/写入全部被 RLS 拒绝。

### P0：通知闭环与深链一致性

- 在已审批设置面板中提供通知权限状态和明确的用户手势入口；保持顶栏无铃铛、通知静默的现行设计。
- 读取云端 `notify_log` 或明确取消“跨设备去重”承诺；同一平台 + 标题 + 日期只提醒一次。
- 通知失败、拒绝、浏览器不支持时仅降级为站内状态，不循环申请权限。
- 统一 URL 状态模型：`p/platform/week/day/view/scope/show` 首次解析、交互回写、刷新恢复和无效值回退必须对称。
- 页面导航更新 `p`；首页读取 `platform`；浏览器前进/后退行为需明确并测试。

验收标准：全新浏览器可从设置完成授权；允许/拒绝两路均有 E2E；分享任一受支持 URL 后，在新上下文恢复相同页面、平台、周、日、视图、范围和搜索条件。

### P1：数据与抓取边界加固

- 新建集中式 `safePlatformUrl`/`validateAnimeItem` 控制，前端、导入、云同步和抓取输出共用契约或共享测试向量。
- 响应体采用 Content-Length 预检 + 流式累计上限；压缩后/解压后均要有限制。
- 为 B站、腾讯、优酷、爱奇艺、豆瓣分别定义重定向允许主机和最大跳转次数。
- 为 tab、卡片、分集、评论和字符串长度设置合理上限；超限按单平台失败处理并沿用上次成功数据。
- 平台超时使用统一 `AbortSignal`；Playwright 页面和浏览器在取消后立即关闭。
- 日志清洗在 `sync.mjs` 的中央 wrapper 完成，避免各抓取器遗漏。

验收标准：合成超大响应、外部/内网重定向、`javascript:`/`data:` URL、异常主机、多行日志、超量 DOM/JSON 均被拒绝；正常四平台回归不受影响。

### P1：一次性设备配对

采用“短时一次性配对 + 已配对设备成员关系”，**不实现长期共享空间码降级**。

- 数据模型：`spaces`、`space_members`、`pairing_requests`；现有数据表增加 `space_id`，并为迁移期保留 `user_id` 所有权校验。
- 配对服务必须由 Supabase Edge Function 或经过严格审计的 RPC 执行；禁止浏览器直接写成员关系。
- 二维码使用至少 128 bit 随机一次 token；手输码只作 5 分钟内的短码索引，必须有按 IP/用户/设备限流、失败次数上限和一次性消费。
- 推荐双向确认：B 发起，A 显示设备摘要并确认；仅知短码不能直接加入空间。
- 成员可列出和撤销；撤销后新请求立即被 RLS 拒绝，已撤销设备的本地缓存不得再上传。
- 迁移采用可回滚事务：为当前用户建默认 space，将现有行归属到该 space，再切换客户端；失败不删除旧行。
- RLS 通过成员关系校验；如使用 `SECURITY DEFINER`，固定 `search_path`、最小授权并覆盖越权测试。

验收标准：二维码和手输码两路成功；过期、复用、暴力尝试、跨用户猜码、撤销后访问全部失败；迁移前后数据一致；日志、URL、分析事件中不出现 token 或短码。

### P2：分享与内容体验

- 在重新审批的设计中加入分享命令：移动端优先 `navigator.share`，桌面复制当前规范化深链；失败可恢复且不显示伪成功。
- 剧集详情/历史面板、豆瓣评分链接、纠错 Issue 入口拆成独立设计评审，不与同步/安全改动同批发布。
- RSS/ICS 先定义数据时区、预测标识、追番隐私和缓存语义，再决定实现。

### P3：运维与远期候选

- Actions 失败自动建 Issue：按失败指纹去重、恢复后自动关闭或标记、限制权限和频率。
- Web Push/Periodic Background Sync、浏览器扩展伴侣、自定义域名、隐私友好统计、公开分享和合规说明另行立项。

## 6. 依赖与风险

| 风险 | 影响 | 控制 |
| --- | --- | --- |
| Supabase 生产 schema 与仓库漂移 | RLS 失效或功能误判 | 只读导出对比；迁移前阻断发布；保留回滚 SQL |
| LWW 时钟偏差 | 新设备覆盖远端数据 | 服务端时间/版本向量或明确的首次拉取规则；冲突测试 |
| 配对短码枚举 | 未授权设备加入 | 双向确认、短 TTL、限流、一次性 token、审计和撤销 |
| 安全加固误伤平台数据 | 抓取量骤降 | 先观测模式记录拒绝原因，再启用阻断；逐平台 allowlist |
| 响应上限过小 | 正常大页面失败 | 基于线上分位数设阈值并留安全余量；单平台回退 |
| 多项并发导致回归难定位 | 发布质量下降 | 每个里程碑独立分支/PR；功能开关；squash merge |
| UI 变更偏离已审批规范 | 设计回归 | V2-G0 前不写 UI；实现零自由发挥；截图台账复核 |

## 7. 测试与发布门禁

每个里程碑至少包含与风险相称的单测和专项 E2E；最终发布严格执行 `AGENTS.md` 的完整清单：

1. `pnpm test` 与 `pnpm build`。
2. `pnpm run qa:app`、`qa:m5`、`qa:m5b`、`qa:m3`。
3. `scripts/verify/youku-today.mjs`、`iqiyi-today.mjs`、`tencent-duration.mjs`、`data-fields.mjs`。
4. Supabase 测试项目的跨设备、RLS、配对、撤销和迁移专项。
5. 提交并推送 `main`，等待 Actions 和 Pages `success`。
6. `pnpm run qa:live` 与人工抽查首页、追番、日历、通知设置、同步状态、深链和移动端。

发布策略：V2-M1/M2/M3 分批发布；数据库迁移先向后兼容，再部署客户端，观察稳定后才清理旧字段。发现跨用户、数据丢失、同步覆盖或大面积抓取下降时立即关闭相应功能开关并回滚客户端；数据库只执行预先演练的向后迁移，不做不可逆在线删除。

## 8. 完成定义

- 功能、数据迁移、权限策略、异常路径和回滚均有自动化证据。
- 线上配置与仓库声明一致，不能用“代码已写”替代真实环境验收。
- 安全扫描加固项有恶意输入回归测试；被拒绝输入可观测但不泄露敏感值。
- 文档、README、AGENTS 数据语义和操作说明同步更新。
- 全量发布门禁、Actions、Pages 和线上 QA 全部成功后，才把对应条目迁入下一版“已完成基线归档”。
